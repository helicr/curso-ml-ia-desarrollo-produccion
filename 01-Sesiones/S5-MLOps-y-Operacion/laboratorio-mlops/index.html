El modelo de retención a 90 días ya está en producción desde S4. Ahora toca lo que hace un equipo de MLOps cada día: medir si los datos o el modelo han cambiado, cambiar de versión y volver atrás sin miedo y dejar que GitHub avise cuando algo se mueve.

2 · L1 · Deriva de datos · qué es y por qué no avisa sola

El modelo sigue funcionando… pero ya no ve a los clientes con los que aprendió

Qué pasa

  • Un modelo no se rompe: sigue devolviendo una probabilidad para cualquier entrada. No avisa de que sus entradas ya no se parecen a las del entrenamiento.
  • Los clientes de hoy compran menos veces al trimestre, o hace más tiempo que no compran: el modelo extrapola.
  • Por eso alguien tiene que medirlo: comparar los datos de hoy con los de referencia.

Cómo se mide

  • Se elige un corte de referencia (el último de entrenamiento) y un corte actual.
  • Para cada una de las 13 variables: PSI (cuánto cambia el reparto) y KS (distancia entre distribuciones).
  • No hace falta la etiqueta: se puede hacer hoy, sin esperar 90 días.
Lo que avisa pronto puede dar falsas alarmas (los datos cambian y el modelo sigue bien). Lo que dice la verdad llega tarde (L2). Se miran las dos.

Datos de hoy

  • Se calculan al vuelo con el mismo SQL de la capa FS que usó el entrenamiento: así la comparación es justa.

Pocos clientes

  • Con 109 y 148 clientes el PSI oscila por azar: es un aviso, no una sentencia.

Solo lectura

  • deriva no escribe nada en la base ni en el registro: lo puedes lanzar sin miedo.

2 · L1 · Deriva de datos · el cálculo con cuatro clientes

El PSI con un ejemplo que cabe en la mano

PSI = suma de (q − p) · ln(q / p)

Con p = fracción de clientes de la referencia en cada intervalo y q = la del corte actual. Los intervalos salen de los cuantiles de la referencia.

intervaloreferencia (p)actual (q)aporte
hasta 2,50,500,750,1014
más de 2,50,500,250,1733
nulo0,00010,00010,0000
PSI0,2747
Codespace · desde 04-Proyecto-Base
# la referencia es [1, 2, 3, 4] y el corte actual [1, 1, 1, 4]
$ python -c "from ia_mlops import deriva; print(round(deriva.psi_detalle([1, 2, 3, 4], [1, 1, 1, 4], intervalos=2)['psi'], 4))"

Qué debes ver: 0.2747. Con la misma muestra en los dos lados, el PSI es exactamente 0.

Las tres franjas (una convención)

  • Menos de 0,10: estable.
  • De 0,10 a 0,25: moderado.
  • Más de 0,25: cambio importante.
  • Es la regla del oficio, no una ley: por eso --umbral-psi la deja cambiar.

El suelo anti-cero

  • ln(q / p) no existe si un intervalo está vacío: las fracciones menores que 0,0001 se suben a 0,0001. Es un parche numérico, no una teoría.

El KS

  • Mira la distancia máxima entre las dos distribuciones acumuladas: 0 iguales, 1 separadas del todo. Es un segundo punto de vista sobre lo mismo.

3 · L2 · Deriva de rendimiento · la etiqueta llega 90 días después

La deriva de rendimiento es la verdad… que llega 90 días tarde

Qué se predice

  • La probabilidad de que el cliente vuelva a comprar en los próximos 90 días.
  • La etiqueta («¿compró?») solo se conoce cuando pasan esos 90 días.
  • El corte 2011-12-10 aparece como «sin etiqueta»: el corte + 90 días se sale de los datos.

Qué se mide

  • El AUC del modelo en producción en cada corte con etiqueta: cómo ordena a los que compran por delante de los que no.
  • Se compara con el primer corte medido: la caída de AUC.
  • La tolerancia por defecto (0,05) es provisional: no sale de ninguna medición.

Línea de tiempo (un corte cualquiera)

Día 0 (corte)Día 0 a 90Día 90
Se calculan las 13 variables y se puntúaNadie sabe todavía quién comprará: solo se puede mirar la deriva de datos (L1)Llega la etiqueta: ya se puede calcular el AUC de ese corte
Por eso se miran las dos: la de datos avisa pronto (pero puede ser falsa alarma) y la de rendimiento confirma tarde.

4 · L3 · Versionar y volver atrás con alias · limitación honesta

Mover el alias no cambia la API que ya está desplegada

Qué gobierna el alias

  • El registro de MLflow y cualquiera que cargue models:/retencion-90d@champion.
  • cargar y las pruebas de este laboratorio.

Qué NO gobierna

  • La imagen Docker de la API copia models/modelo_mlflow al construirse y no lee el registro.
  • Mover champion no cambia lo que responde la API ya desplegada.

Cómo se uniría en un sistema real (tres líneas; aquí no se implementa)

  1. Al mover el alias, un paso del workflow exporta la versión champion a models/modelo_mlflow.
  2. Construye y publica la imagen con la versión en su etiqueta.
  3. La despliega (o hace que la API cargue por alias al arrancar).

Volver a la muestra (si quieres repetir L1 y L2)

  • Registrará una v3 (igual que la v1) y el alias no se mueve.

5 · L4 · Alertas con GitHub Actions · qué hace monitoreo.yml

El mismo deriva, pero cada día y sin que nadie mire

5 · L4 · Alertas con GitHub Actions · paso 1 · en la raíz del repositorio

Copia monitoreo.yml a .github/workflows en una rama base

Codespace · terminal bash · RAÍZ del repositorio
# sal de 04-Proyecto-Base (si estás dentro)

Este push no lanza el workflow: lab/mlops-s5 no es una rama de ensayo. Run workflow solo aparece si el archivo está en la rama por defecto; por eso los ensayos usan ramas.

Qué debes ver

Si falla

  • git push da 403: el gestor de credenciales tiene otra cuenta (git-credential-manager github login).
  • No aparece el workflow: comprueba que el archivo está en .github/workflows/ de la rama y que activaste las Actions.

5 · L4 · Alertas con GitHub Actions · qué abre el workflow

El aviso de verdad: un issue con las variables y el enlace al run

Qué debes ver

  • En la pestaña Issues hay uno nuevo, con la etiqueta alerta-deriva (se crea sola si no existe).
  • Título: «Alerta de deriva: 5 variables superan el PSI 0.25 (referencia 2010-12-01, actual 2011-12-10)».
  • Cuerpo: la tabla de las cinco variables que superan el umbral con su PSI y su KS, el enlace al run y qué hacer.
Qué hacer con la alerta: abre el run, lee el resumen y decide si la deriva es esperable (antiguedad_dias) o de comportamiento (recencia_dias, frecuencia_90d…). Si el AUC de cortes de prueba cae, reentrena y promueve la versión nueva con alias (L3); si sale mal, volver.

Verificado en Actions (26/11): gh issue create funciona con solo issues: write, y un segundo run comenta en el mismo issue.

5 · L4 · Alertas con GitHub Actions · repetir y limpiar

Si repites el run, no se abre un segundo issue

Qué debes ver

  • En la página del run, Re-run all jobs: vuelve a medir y a dar rojo.
  • Qué verás (ensayado en Actions el 26/11): el trabajo 3 comenta en el issue que ya está abierto («Nueva medición con deriva») y no abre otro.
  • Así una deriva que sigue ahí no llena la lista de issues: una alerta abierta hasta que alguien la cierre.

Si falla

  • gh: Resource not accessible by integration: faltan permisos de escritura de issues; en Settings › Actions › General, comprueba que el workflow puede escribir.
  • El issue no se crea: mira el paso «Abrir el issue» del trabajo 3.

Al terminar, limpia

  • Cierra el issue (botón Close issue).
  • Borra las dos ramas de ensayo (órdenes de abajo).
  • Desactiva el workflow en Actions («···» › Disable workflow): con datos congelados, el schedule diario avisaría siempre.
Terminal bash · raíz del repositorio
$ git push origin --delete lab/monitoreo/estable
$ git push origin --delete lab/monitoreo/deriva
