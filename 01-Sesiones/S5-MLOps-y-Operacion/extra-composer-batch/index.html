1 · Por qué y qué · del cron al orquestador

¿Por qué no basta un cron o un workflow? Porque un lote real tiene pasos, dependencias y fallos

Lo que ya hace puntuar-lote.yml (S4)

  • Un workflow de Actions con schedule entrena, construye la API y puntúa a todos los clientes.
  • Funciona y es barato: para un lote diario aislado, puede ser suficiente.

Lo que añade un orquestador

  • Dependencias: validar solo si el lote terminó; resumir solo si validó.
  • Reintentos y estado por tarea: ves qué tarea falló y la repites sola.
  • Historial y botón: cada ejecución queda guardada y se lanza con parámetros.
  • Un sitio donde coordinar muchos flujos (ingesta, lote, monitoreo…).
Decisión del profesor: Cloud Composer. Se justifica cuando hay muchos flujos que coordinar. Para uno solo, Cloud Run Jobs o el propio Actions cuestan mucho menos: el README lo dice sin cifras inventadas.

Fuente: puntuar-lote.yml de S4 y README de este extra.

1 · Por qué y qué · imagen → pod → salida → validación

La imagen lleva el modelo; el DAG la ejecuta, valida la salida y la resume

La imagen

  • La imagen de la API lleva el modelo, pero no el SQL ni los datos (su .dockerignore los excluye).
  • lote.Dockerfile parte de ella y los añade: sirve con el Dockerfile de develop y con el multi-etapa (--build-context modelo=…).

Dos operadores

  • Composer: KubernetesPodOperator con la imagen de Artifact Registry.
  • Local: DockerOperator con el socket de Docker.
  • Se elige con LOTE_MODO; si falta el proveedor, el DAG se importa igual.

La salida

  • explotacion escribe campana_<corte>.csv y .json en /tmp/reports del contenedor.
  • El pod devuelve un resumen pequeño por XCom; no se guarda la lista de clientes fuera.

Sin verificar El DAG no se ha ejecutado en un Airflow real: ni con Docker ni en Composer.

2 · Preparar el lote y escribir el DAG · dags/retencion_lote.py

El DAG: cinco tareas encadenadas, sin schedule y con cuatro parámetros

dags/retencion_lote.py · la definición
with DAG(
    dag_id=DAG_ID,
    description='Puntuación por lotes de todos los clientes (ia_mlops.explotacion) en la imagen que lleva el modelo.',
    schedule=None, start_date=datetime(2026, 1, 1), catchup=False, max_active_runs=1,
    tags=['curso', 'retencion', 'lote'], doc_md=__doc__,
    params={
        'corte': Param('', type='string', pattern=r'^(\d{4}-\d{2}-\d{2})?$', description='AAAA-MM-DD; vacío = el día siguiente a la última factura'),
        'imagen': Param('', type='string', description='registro/ruta:etiqueta de la imagen del lote; vacío = LOTE_IMAGEN_DEFECTO'),
        'capacidad': Param(0.10, type='number', minimum=0.01, maximum=1, description='fracción de clientes a los que llega la campaña'),
        'huella_esperada': Param('', type='string', description='opcional: huella de datos que debe tener el modelo de la imagen'),
    },
) as dag:
    entradas = PythonOperator(task_id='entradas', python_callable=_validar_entradas_tarea)
    comprobar = operador('comprobar', ['python', '-c'], [ORDEN_COMPROBAR])
    ejecutar = operador('ejecutar_lote', ['sh', '-c'], [ORDEN_LOTE, 'lote', '{{ params.corte }}', '{{ params.capacidad }}'], ENTORNO_LOTE)
    validar = PythonOperator(task_id='validar', python_callable=_validar)
    resumir = PythonOperator(task_id='resumir', python_callable=_resumir)
    entradas >> comprobar >> ejecutar >> validar >> resumir

Qué debes ver

  • Sin schedule: se lanza a mano, por la API o por Actions.
  • max_active_runs=1: dos lotes a la vez no tienen sentido.
  • Cuatro params: corte, imagen, capacidad, huella_esperada; el formulario de Airflow los valida.

Las cinco tareas

  • entradas: valida lo que escribió una persona antes de lanzar nada.
  • comprobar: qué modelo lleva la imagen.
  • ejecutar_lote: python -m ia_mlops.explotacion.
  • validar y resumir corren en el worker.

Composer · KubernetesPodOperator
def pod(task_id, cmds, argumentos, entorno=None):
    try:
        from airflow.providers.cncf.kubernetes.operators.pod import KubernetesPodOperator
    except ImportError:
        return _tarea_que_falla(task_id, 'Falta apache-airflow-providers-cncf-kubernetes (viene con Cloud Composer). '
                                         'En local usa LOTE_MODO=docker.')
    comunes = dict(
        task_id=task_id, name=task_id.replace('_', '-'), namespace=NAMESPACE,
        image='{{ params.imagen or "' + IMAGEN_DEFECTO + '" }}',
        cmds=list(cmds), arguments=list(argumentos), env_vars=entorno or {},
        get_logs=True, do_xcom_push=True, startup_timeout_seconds=600,
        config_file='/home/airflow/composer_kube_config', kubernetes_conn_id='kubernetes_default',
    )
    try:
        return KubernetesPodOperator(on_finish_action='delete_pod', **comunes)          # proveedor reciente
    except TypeError:
        return KubernetesPodOperator(is_delete_operator_pod=True, **comunes)             # proveedor antiguo
Local · DockerOperator
def contenedor(task_id, cmds, argumentos, entorno=None):
    try:
        from airflow.providers.docker.operators.docker import DockerOperator
    except ImportError:
        return _tarea_que_falla(task_id, 'Falta apache-airflow-providers-docker. Instálalo (pip install apache-airflow-providers-docker) '
                                         'o usa LOTE_MODO=kubernetes en Cloud Composer.')
    return DockerOperator(
        task_id=task_id, image='{{ params.imagen or "' + IMAGEN_DEFECTO + '" }}',
        command=list(cmds) + list(argumentos), environment=entorno or {},        # la imagen de la API solo define CMD: command lo sustituye
        docker_url=leer_ajuste('LOTE_DOCKER_URL', 'unix://var/run/docker.sock'), auto_remove='success', mount_tmp_dir=False,
        tty=False, force_pull=False,
    )

Lo que dice la documentación

  • En Composer 3 los pods corren siempre en composer-user-workloads; config_file es /home/airflow/composer_kube_config.
  • XCom del pod: el contenido de /airflow/xcom/return.json.
  • DockerOperator es del paquete apache-airflow-providers-docker; sin XCom completo recoge la última línea de salida.

Fuente: <https://docs.cloud.google.com/composer/docs/composer-3/use-kubernetes-pod-operator> y la documentación del proveedor Docker.

La tarea «validar» no se fía: filas, probabilidades en [0,1], tramos y modelo

dags/lote_logica.py · validar_salida (extracto)
def validar_salida(resumen, comprobar=None, huella_esperada=None):
    """En el WORKER. Comprueba el resumen del lote. Devuelve la lista de avisos (no graves); lanza ErrorSalida si algo falla.

    resumen          lo que devolvió resumir_salida() dentro del contenedor
    comprobar        lo que dijo la tarea «comprobar» (modelo y huella que lleva la imagen); si se da, deben coincidir
    huella_esperada  huella de datos que se exige a la imagen (parámetro opcional del DAG)
    """
    fallos, avisos = [], []
    if not isinstance(resumen, dict):
        raise ErrorSalida(f'la tarea del lote no devolvió un resumen (llegó {type(resumen).__name__}); mira el registro del contenedor')
    filas = resumen.get('filas') or 0
    if filas <= 0:
        fallos.append('el lote no puntuó a ningún cliente (0 filas)')
    if resumen.get('clientes_puntuados') != filas:
        fallos.append(f'filas del CSV ({filas}) distintas de clientes_puntuados del JSON ({resumen.get("clientes_puntuados")})')
    if resumen.get('nulos'):
        fallos.append(f'{resumen["nulos"]} probabilidades vacías o no numéricas')
    lo, hi = resumen.get('prob_min'), resumen.get('prob_max')
    if filas and (lo is None or hi is None or not (0.0 <= lo <= hi <= 1.0)):
        fallos.append(f'probabilidades fuera de [0, 1]: mínima {lo}, máxima {hi}')
    tramos = resumen.get('tramos') or {}
    if set(tramos) != {n for n, _ in TRAMOS}:
        fallos.append(f'tramos inesperados: {sorted(tramos)}')
    elif sum(tramos.values()) != filas - (resumen.get('nulos') or 0):
        fallos.append(f'los tramos suman {sum(tramos.values())} y no {filas}')
    if filas >= 10 and resumen.get('deciles') != list(range(1, 11)):
        fallos.append(f'deciles inesperados: {resumen.get("deciles")} (se esperaba 1..10)')
    esperados = max(1, math.ceil(float(resumen.get('capacidad') or 0) * filas)) if filas else 0
    if resumen.get('en_campana') != esperados:
        fallos.append(f'la campaña tiene {resumen.get("en_campana")} clientes y por la capacidad {resumen.get("capacidad")} deberían ser {esperados}')

6 · Automatizarlo con GitHub Actions · el workflow que lo lanza

lote-composer.yml: aprobación, entrada sin claves y falla si el DAG falla

lote-composer.yml · el trabajo «lanzar»
  lanzar:
    name: 2 · Lanzar el DAG en Composer y esperar (con aprobación)
    needs: entradas
    runs-on: ubuntu-latest
    timeout-minutes: 90
    environment: produccion          # aquí se para hasta que un revisor lo apruebe (Review deployments)
    permissions:
      contents: read
      id-token: write                # para que GitHub pida a Google el token de corta vida (WIF): sin claves
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - name: Entrar en Google Cloud sin claves (Workload Identity Federation)
        uses: google-github-actions/auth@v2
        with:
          project_id: ${{ vars.GCP_PROYECTO }}
          workload_identity_provider: ${{ vars.GCP_PROVEEDOR_WIF }}
          service_account: ${{ vars.COMPOSER_CUENTA }}
      - uses: google-github-actions/setup-gcloud@v2
      - name: Averiguar la URL del Airflow del entorno
        id: airflow
        run: |
          URL=$(gcloud composer environments describe "${{ vars.COMPOSER_ENV }}" --location "${{ vars.COMPOSER_REGION }}" --format="value(config.airflowUri)")
          if [ -z "$URL" ]; then echo "::error::El entorno no devolvió config.airflowUri: ¿existe y está en marcha?"; exit 1; fi
          echo "url=$URL" >> "$GITHUB_OUTPUT"
      - name: Lanzar el DAG retencion_lote y esperar (falla si el DAG falla)
        env:
          AIRFLOW_URL: ${{ steps.airflow.outputs.url }}
        run: |
          # La salida del script ya escribe el resumen en GITHUB_STEP_SUMMARY (página del run).
          python "$EXTRA/lanzar_lote.py" --url "$AIRFLOW_URL" --auth google --corte "$CORTE" --imagen "$IMAGEN" --capacidad "$CAPACIDAD" --espera 4800

Qué debes ver

  • Run workflow pide corte, imagen y capacidad; el job «lanzar» espera la aprobación.
  • La página del run trae la tabla de tareas y el registro de resumir.

Si falla

  • ::error::El entorno no devolvió config.airflowUri → no existe o no está en marcha.
  • Run en rojo con failed → mira el registro de la tarea que imprime el propio script.
