Del alias champion de MLflow a un endpoint de Vertex AI

En S5 aprendimos que el alias champion decide qué modelo manda en MLflow. Pero lo que responde a un cliente es un servicio desplegado. Este extra une las dos cosas: el champion de MLflow dentro de una imagen propia, en un endpoint de Vertex AI, desplegado y deshecho desde GitHub Actions.

Cómo seguirlo

Cada orden lleva ⧉ para copiarla. Las de L1 y L2 se pegan en una terminal bash en extra-vertex-champion y no necesitan nube; las de L3 a L6 van en Cloud Shell y cuestan dinero mientras haya algo desplegado. En cada paso: qué debes ver (salida real), si falla y, cuando falta, un recuadro «Captura pendiente». ← → avanzan · O índice · S notas · F pantalla completa · clic en una captura para ampliarla y Esc para cerrarla.

Honestidad: todo lo que corre sin nube está ejecutado y probado. Vertex AI, Artifact Registry, GitHub Actions y Docker no se han ejecutado todavía: se marca «sin verificar» y se deja la receta del ensayo.

1 · Qué vamos a hacer · el problema

Mover el alias no cambia lo que responde

En MLflow, @champion es un puntero. La imagen de la API no lee ese registro: se construye con el modelo dentro.
Sin el enlaceCon el enlace de este extra
Cambias el alias y nada cambia en producciónLa versión que manda es la que se publica: misma versión, misma huella, mismas métricas
Nadie sabe qué versión de MLflow respondeCada predicción lleva version_mlflow; cada versión de Vertex, sus etiquetas (huella, AUC)
Volver atrás = reconstruir y desplegar a manovolver.sh mueve el tráfico y el alias a la vez
El servicio de Vertex de S4 devolvía la claseUna imagen propia devuelve la probabilidad, la clase y el tramo

Qué aporta Vertex AI

  • Un Model Registry con versiones, alias y etiquetas.
  • Un endpoint HTTPS gestionado, con reparto de tráfico entre versiones (el canario).
  • Escala y registros en Cloud Logging.

Qué cuesta

  • Un endpoint cobra mientras tenga un modelo desplegado, aunque no reciba peticiones.
  • Precio: sin dato ([precios de Vertex AI](https://cloud.google.com/vertex-ai/pricing)).
  • Por eso hay un borrar.sh y un workflow para borrar.

1 · Qué vamos a hacer · vocabulario

Las palabras de Vertex AI que vamos a usar

PalabraQué significa aquí
Model RegistryEl catálogo de modelos de Vertex AI. Un modelo tiene versiones (1, 2, 3...). Es el equivalente del registro de MLflow
Versión y aliasCada subida con --parent-model es una versión nueva del mismo modelo. Un alias (champion, mlflow-v6) es un nombre para una versión
EndpointEl servicio HTTPS gestionado. Recibe peticiones y las reparte entre los modelos desplegados en él. Cobra mientras tenga un modelo desplegado
Modelo desplegadoUna versión puesta en un endpoint, con su máquina (e2-standard-2) y sus réplicas. Tiene un id distinto del de la versión
Tráfico (traffic split)El reparto en % entre los modelos desplegados: 0=10,1000=90. La clave 0 es el modelo que se despliega ahora. Debe sumar 100
CanarioDesplegar la versión nueva con poco tráfico (10 %), probarla con peticiones reales y solo entonces darle el 100 %
Contenedor propioUna imagen tuya que cumple el contrato de Vertex (AIP_HTTP_PORT, ruta de salud, ruta de predicción). Frente al pre-construido, que solo devuelve la clase
Artifact RegistryDonde se guarda la imagen. Debe ser regional y de la misma región que el endpoint (no multirregional)
WIFWorkload Identity Federation: GitHub pide a Google un token de corta vida con su identidad OIDC. Sin claves

3 · L2 · El adaptador y la imagen · documentación oficial

Un contenedor propio tiene que cumplir cuatro cosas

Variable o rutaQué es
AIP_HTTP_PORTel puerto (8080 si no existe); se toma de --container-ports. El servidor escucha en 0.0.0.0
AIP_HEALTH_ROUTEruta de salud: debe responder 200 en menos de 10 s (--container-health-route)
AIP_PREDICT_ROUTEruta de predicción (--container-predict-route)
AIP_STORAGE_URIvacía si no hay --artifact-uri: no hace falta si el modelo va en la imagen
EntradaPOST con {"instances": [...], "parameters": ...}
Salida{"predictions": [...]}, una por instancia

Lo que manda la documentación

  • No definas variables con el prefijo AIP_ (las pone Vertex): el Dockerfile no lleva ENV AIP_....
  • La imagen debe estar en Artifact Registry regional, de la misma región que el endpoint.
  • El agente de servicio de Vertex necesita roles/artifactregistry.reader: automático si la imagen es del mismo proyecto.
  • Límite de 1,5 MB por petición y respuesta en un endpoint público compartido.

Fuente: docs.cloud.google.com/vertex-ai/docs/predictions/custom-container-requirements (27/11/2026). La documentación no dice si se pueden añadir campos al nivel superior de la respuesta: la versión de MLflow va dentro de cada predicción.

3 · L2 · El adaptador y la imagen · imagen/vertex_adaptador.py

Lo esencial del adaptador: validar, predecir, devolver

imagen/vertex_adaptador.py (extracto: la predicción y el tramo)
    def predecir(self, filas):
        """filas: lista de diccionarios ya validados. Devuelve una lista de dicts de predicción (uno por fila)."""
        import pandas as pd
        df = pd.DataFrame(filas)[self.variables]
        df['dias_medios_entre_compras'] = pd.to_numeric(df['dias_medios_entre_compras'], errors='coerce').astype('float64')
        prob = self.modelo.predict_proba(df)[:, 1]
        return [{'probabilidad': float(p), 'clase': int(p >= UMBRAL_CLASE), 'tramo': tramo(float(p)), 'version_mlflow': self.version}
                for p in prob]

def tramo(probabilidad):
    """Segmento de negocio (config.SEGMENTOS_RECOMPRA): el primero cuyo «desde» no supera la probabilidad."""
    for s in config.SEGMENTOS_RECOMPRA:
        if probabilidad >= s['desde']:
            return s['segmento']
    return config.SEGMENTOS_RECOMPRA[-1]['segmento']

Qué hace

  • Carga modelo_mlflow/ de la imagen y comprueba la firma contra config.FEATURES y el esquema de la API: si no coincide, la salud da 503 (Vertex no envía tráfico).
  • Cada instancia es una lista de 13 números en el orden de FEATURES; solo dias_medios_entre_compras admite null.
  • Aplica las mismas reglas que la API de S2 (esquemas.Cliente): rangos y coherencia.
  • Nunca registra los valores recibidos: solo cuántas instancias, el código y el milisegundo.

Qué devuelve

  • probabilidad (predict_proba), clase (1 si ≥ 0,5), tramo (alta, media, baja de config.SEGMENTOS_RECOMPRA) y version_mlflow.

3 · L2 · El adaptador y la imagen · imagen/Dockerfile.vertex

La imagen: el mismo lock que la API, el modelo dentro, sin AIP_*

imagen/Dockerfile.vertex (sin comentarios)
FROM python:3.11-slim
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1 \
    CURSO_MODELO_DIR=/app/modelo
WORKDIR /app
COPY requirements-api.lock .
RUN pip install -r requirements-api.lock
COPY ia_mlops/ ia_mlops/
COPY vertex_adaptador.py .
COPY modelo/ modelo/
RUN useradd --uid 10001 --no-create-home --shell /usr/sbin/nologin apiuser
USER 10001
EXPOSE 8080
CMD ["python", "vertex_adaptador.py"]

Qué debes ver

  • Sin variables AIP_*, sin :latest y sin root (USER 10001).
  • --platform linux/amd64: Vertex es amd64; en un Mac con chip ARM sin él la imagen no arrancaría.
Compatible con las dos formas de construir la API. La de develop (COPY models/modelo_mlflow) y la multietapa (--build-context modelo=models): esta imagen no usa ninguna. preparar_contexto.py reúne el mismo requirements-api.lock, tres archivos de ia_mlops y el modelo exportado del registro, y se niega si el modelo y el lock tienen otro scikit-learn.

6 · L5 · Los tres workflows de GitHub Actions · limitación honesta

El registro de MLflow del curso es local: el runner crea el suyo

Lo que hace el workflow hoy

  • models/mlflow.db no está en git. Como nueva-version.yml de S4, el runner entrena con la muestra y crea su propio registro.
  • El champion de ese run no es «el de tu portátil»: es el de ese run.
  • Con dos_versiones entrena dos veces y promueve en cadena (v1, luego v2) para que exista una anterior a la que volver.
  • El alias de MLflow no se mueve desde el rollback del workflow: el registro del runner desaparece.

Lo que haría una empresa

  • Un servidor de MLflow compartido (CURSO_MLFLOW_URI): el workflow leería ese champion.
  • Las etiquetas vertex_* se escribirían ahí con manifiesto_champion.py anotar (paso condicional ya escrito).
  • Sin verificar: nunca se ha ejecutado con un servidor compartido.
Resumen: el workflow demuestra el mecanismo (puerta, imagen, aprobación, canario, rollback). Con un registro local no demuestra «el champion de mi portátil». Está dicho en el propio workflow, en la guía y aquí.

7 · L6 · Coste y borrado · borrar

Lo que cobra es lo que está desplegado: bórralo

Qué cobra y qué no

  • Un endpoint cobra mientras tenga un modelo desplegado, aunque no reciba peticiones.
  • Con dos versiones desplegadas: dos máquinas (e2-standard-2 × 1 cada una).
  • Subir el modelo y la imagen: almacenamiento. Un modelo sin desplegar no usa máquinas.
  • Precio: sin dato ([precios de Vertex AI](https://cloud.google.com/vertex-ai/pricing)).
