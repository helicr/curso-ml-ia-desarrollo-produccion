2 · Práctica 1: Docker, Artifact Registry y Cloud Run · qué aprendes y qué crea

De una imagen Docker a una URL privada en Cloud Run

Qué aprendes

  • Imagen frente a contenedor: la imagen es la receta; el contenedor, la receta en marcha.
  • Un registro de imágenes (Artifact Registry) es el almacén de Google, el equivalente de GHCR.
  • Una etiqueta fija (v1), nunca latest: así sabes qué versión corre.
  • Un servicio privado: solo entra quien demuestra su identidad, sin claves.
  • Cloud Run escala a cero: sin llamadas, no hay nada encendido.
Es la misma imagen de la API de retención de S2: aquí solo cambia dónde corre.

Qué crea

RecursoNombre
Repositorio Docker de Artifact Registrycurso-ml-imagenes
Imagensouthamerica-west1-docker.pkg.dev/project-curso-ml-ia/curso-ml-imagenes/retencion-api:v1
Servicio de Cloud Run (privado, 0 a 1 instancias, 1 GiB)retencion-api-practica

Antes de empezar

  • Tiempo estimado 20-30 min (estimado, sin medir): el docker push de la imagen es lo más lento.
  • Coste: sin dato. Con 0 instancias en reposo no hay instancia cobrando; sí hay almacenamiento de la imagen mientras exista.
  • Se llama retencion-api-practica y no retencion-api para no pisar el servicio del Cloud Journey.

1 · Crear

Los tres objetos básicos

ObjetoEn una frase

5 · Práctica 4: el modelo en Vertex AI · qué aprendes y qué crea

Nuestro modelo en Vertex AI: registro, endpoint y predicción online

Qué aprendes

  • Registrar el modelo en el Model Registry, desplegarlo en un endpoint (un servicio HTTPS gestionado) y pedirle una predicción online.
  • Deshacerlo todo en orden: undeploy → endpoint → modelo → bucket.

Un detalle de versiones

El proyecto usa scikit-learn 1.9.1 y los contenedores pre-construidos de Vertex solo llegan a la 1.6. Un modelo guardado con una versión no debe abrirse con otra, así que crear.sh reentrena el mismo modelo (misma regresión logística, mismos datos y 13 variables) con scikit-learn 1.6.1 y compara su AUC con el del proyecto (0.6982): deben ser casi iguales.

Qué crea

RecursoNombre
Bucket (sin acceso público) con modelo/model.joblibproject-curso-ml-ia-curso-ml-vertex
Modelo en el Model Registryretencion-90d-sklearn
Endpoint (1 réplica e2-standard-2)retencion-90d-endpoint

La petición: una lista, no un diccionario

{"instances": [[13 números]]}, con las variables en el orden del modelo: recencia_dias, frecuencia, monto_total, ticket_medio, unidades_total, productos_distintos, antiguedad_dias, frecuencia_90d, monto_90d, frecuencia_180d, dias_medios_entre_compras, devoluciones, es_reino_unido. Si cambias el orden, el modelo no avisa: devuelve otra cosa.

1 · Crear

bash crear.sh: reentrena con scikit-learn 1.6.1, registra el modelo, crea el endpoint y despliega (10-15 min).

2 · Probar

bash probar.sh: predicción online de dos clientes y comparación con el modelo local.

3 · Borrar, ya

bash borrar.sh enseguida: el endpoint cobra mientras exista.

6 · Práctica 5: Gemini explica la predicción · qué aprendes y qué crea

Gemini explica la predicción: el modelo calcula, el LLM solo redacta

Sus 13 variables (el cliente activo o dormido de clientes_ejemplo.json).

2 · El modelo

La regresión logística calcula la probabilidad y el peso exacto de cada variable.

3 · Gemini

Solo redacta en español con esos números; no calcula nada.

El script mira que el texto cite la probabilidad del modelo.

6 · Práctica 5: Gemini explica la predicción · paso 3 · en Cloud Shell

Un aviso que era falso y cómo cerrar la práctica

Lo que escribió Gemini

«Este cliente tiene una probabilidad del 82.79% de realizar una compra en los próximos 90 días, situándose en un tramo de probabilidad alta.»

El aviso de la captura

  • Visto (25/11): el script avisó «el texto no cita el 82.8 %» aunque Gemini sí escribió «82.79%». Era un falso positivo: solo buscaba «83» y «82.8».
  • Arreglo: explicar_prediccion.py acepta la cifra con 1 o 2 decimales, coma o punto (82,8 · 82.8 · 82,79 · 82.79); tiene su prueba. No se repitió la llamada real en Cloud Shell: sin verificar allí.
Lección: los números los pone el modelo; el LLM solo los cuenta. Comprobar que cita la cifra es buena idea, pero la comprobación también puede equivocarse: revisa el texto.

7 · Borrar, costes y cierre · lo que aprendimos de verdad

Costes y lecciones reales

El endpoint cobra encendido

Vertex cobra mientras tenga un modelo desplegado, aunque no reciba peticiones. El clúster de GKE, igual. Importe: sin dato.

El crédito no lo cubre todo

La prueba gratuita no cubre la plataforma Gemini/Vertex en cuentas dadas de alta desde el 16/11/2026: borra enseguida.

Cuenta de Compute, sin roles

En una organización nueva no tiene ningún rol: el clúster de GKE quedó en ERROR. Solución: sa-gke-nodos.

IAM tarda en propagarse

Un rol recién concedido puede no valer aún: dataproc.autoscalingPolicies.use denied. Se esperan 120 s.

Spark ignora los nulos

countDistinct no cuenta los nulos, como COUNT(DISTINCT): las compras sin cliente no suman clientes.

Vertex devuelve la clase

El contenedor pre-construido llama a predict(): 1 o 0, no la probabilidad. Tildes: en gcloud, sin tildes.
