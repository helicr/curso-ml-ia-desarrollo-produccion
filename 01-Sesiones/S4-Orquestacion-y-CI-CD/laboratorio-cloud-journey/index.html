2 · Preparar Google Cloud · paso 3 · el mecanismo

WIF: GitHub demuestra quién es y recibe acceso temporal

1 · El token

Cada ejecución de Actions puede pedir a GitHub un token OIDC que dice qué repositorio es. Necesita el permiso id-token: write.

2 · El cambio

Google comprueba el token contra el pool y el proveedor y la condición del repositorio. Solo si cuadra, lo cambia por acceso temporal.

3 · El permiso

El acceso es el de una cuenta de servicio con permisos mínimos: subir la imagen y desplegar. Caduca en minutos.

7 · Borrar y cerrar · lo que aprendimos de verdad

Costes y lecciones reales

0 instancias en reposo

Con --min-instances=0 no hay nada encendido cuando nadie llama. --max-instances=1 pone un tope. Importe del uso: sin dato.

Presupuesto con alertas

El de 20 € avisa al 50, 90 y 100 %, pero no corta nada: sigues siendo tú quien borra.

Sin claves, por política

La organización prohíbe crear claves de cuentas de servicio: WIF no es un capricho: es la vía que queda.

La cuenta de Compute, sin roles

En una organización nueva, la cuenta de servicio de Compute no tiene ningún rol. Con ella GKE se rompió (práctica 02).

Gemini no está en Santiago

Para Gemini se usa la ubicación global (práctica 05). El resto del laboratorio va en southamerica-west1.

Tildes en Cloud Shell

Al teclear desde otra herramienta se perdieron («Imgenes»): descripciones de gcloud sin tildes.
