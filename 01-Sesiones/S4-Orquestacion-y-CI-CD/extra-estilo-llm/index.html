S4 · Extra · Un LLM y el estilo de color

Antes de afinar un LLM, mide una línea base barata

En 60 minutos sigues, paso a paso, un experimento completo: un LLM de visión pequeño intenta leer el estilo de color de una foto, una regresión que entrena en segundos le gana, y después el mismo LLM sí funciona explicando con palabras. Al final lo orquestas en GitHub Actions.

Cómo seguirla

  • Cada orden lleva ⧉: cópiala y pégala en tu terminal. Copiar todo copia el bloque entero.
  • Las salidas y las capturas son reales: salen de los notebooks ya ejecutados. Clic en una captura para ampliarla; Esc la cierra.
  • El extra es opcional: no entra en la tarea ni en la rúbrica.
  • Teclas: ← → avanzar · O índice · S notas · F pantalla completa.

A · La idea

Tres actos, un mensaje

Acto 1 · El LLM intenta leer el estilo

¿Puede SmolVLM-256M escribir los 5 ajustes como JSON? (notebooks 02 y 03)

  • Sin entrenar (A): 55 % de JSON válido.
  • Con LoRA (B): 100 % de JSON válido, pero su error (0,310) es peor que contestar siempre la media (0,259).
  • Aprende el formato, no la tarea.

Acto 2 · Una línea base barata

¿Y si no usamos un LLM? (notebook 04)

  • Una regresión (Ridge) sobre 27 estadísticas de color entrena en segundos.
  • Error 0,151: es la mejor de todas.
  • Se registra en MLflow como produccion.

Acto 3 · El LLM explica en español

¿Y si le damos una tarea de lenguaje? (notebook 05)

  • Con LoRA, 100 % de sentido correcto frente a 40,7 % sin entrenar.
  • Pero fluido no es correcto: 18,3 % de frases con algún ajuste inventado.
El mensaje. Usa cada herramienta para lo que sirve. Para medir un color, unas estadísticas y una regresión son más baratas y más exactas; el LLM brilla redactando. Y siempre: mide primero la línea base («contestar la media»); si tu modelo no la mejora, no ha aprendido nada de la foto.

Los datos se fabrican: a una foto se le aplican cinco ajustes de color conocidos (exposición, temperatura, tinte, contraste, saturación) y así la etiqueta sale exacta y gratis. Cifras de la configuración de clase: 300 fotos, 60 de test.

A · Glosario

Diez palabras para seguir el extra

TérminoQué significa aquí
LLM / VLMModelo de lenguaje grande: escribe texto palabra a palabra. El VLM (de visión) también mira una imagen. SmolVLM-256M: 256 millones de parámetros.
Zero-shot / one-shotPreguntar sin enseñar ningún ejemplo, o dando uno solo en la pregunta. No se entrena nada.
Fine-tuning y LoRAAfinar = seguir entrenando con tus datos. LoRA lo hace barato: congela el modelo y entrena matrices pequeñas añadidas.
AdaptadorEl archivo con esas matrices (7 MB), aparte del modelo base (494 MB).
JSONTexto con pares «nombre: valor», p. ej. {"exposicion": 0.3}.
TérminoQué significa aquí
MAE normalizadoError medio entre ajuste predicho y real, dividido por el ancho de su rango. 0 es perfecto.
RidgeRegresión lineal con penalización contra coeficientes exagerados; entrena en segundos.
ΔE, SSIMΔE: diferencia de color con el resultado ideal (menor es mejor). SSIM: estructura conservada (1 = idéntica).
AlucinaciónQue el modelo afirme algo que no está en la entrada: aquí, mencionar un ajuste que no se tocó.
papermillEjecuta un notebook desde la terminal cambiándole parámetros y guarda una copia ya ejecutada.

D · Actions · la idea

Cada notebook es un job

0 · Pruebas ─► 1 · Preparar (00) ─► 2 · Datos (01) ─┬─► 3a · Zero-shot, A (02) ───────────┐
                                                    ├─► 3b · LoRA, B (03) ────────────────┼─► 4 · Comparar (04) ─┐
                                                    ├─► 3c · Base C y Reinhard D (04) ────┘                      ├─► 5 · Resumen
                                                    └─► 3d · Acto 3, explicar (05) ───────────────────────────────┘
Los cuatro jobs 3a, 3b, 3c y 3d tienen el mismo needs: datos: corren a la vez. Los dos últimos esperan: comparar a 3a, 3b y 3c; resumen a comparar y a explicar.

Cuatro ideas

  • Job: un trabajo del workflow, en una máquina nueva (ubuntu-latest, sin GPU). needs: dice de qué otro depende.
  • papermill: ejecuta el notebook e inyecta parámetros; la copia ejecutada se sube siempre (if: always()).
  • Artefactos: lo que un job produce lo sube y el siguiente lo baja. Caché: el modelo y las fotos no se bajan en cada job.
  • Parámetros pequeños (60 fotos, 2 épocas): comprueban que el pipeline funciona; las conclusiones se sacan con la configuración de clase.

Terminal · Codespace
$git switch develop
$git pull
$git switch -c lab/extra-estilo-llm

Antes de empezar

  • Antes, entra en la pestaña Actions de tu fork: en los forks puede venir desactivado. Si ves un aviso que pide activar los workflows, acéptalo.
  • Tu fork debe tener la carpeta del extra en la rama de la que partes.

Sin terminal (solo la web de GitHub)

  • En tu fork, en el selector de ramas elige develop, escribe lab/extra-estilo-llm y crea la rama a partir de develop.
El nombre debe empezar por lab/: es lo que escucha el disparador del workflow (push a lab/**). Con otro nombre, no se lanza nada.

D · Actions · paso 2 de 4

Copiar el YAML a .github/workflows/

Ruta A · en la web de GitHub

  • En el repositorio, abre extra-estilo-llm.yml y pulsa Raw; selecciona todo y copia.
  • Ya en tu rama lab/extra-estilo-llm: Add file → Create new file.

  • Pega el contenido y Commit changes… directamente en la rama lab/extra-estilo-llm, no en develop.
No teclees el YAML a mano: la sangría se rompe. Cópialo con Raw.

D · Actions · paso 3 de 4

Commit y push: ahí arranca el run

Terminal · en la rama lab/extra-estilo-llm
$git status
$git add .github/workflows/extra-estilo-llm.yml
$git commit -m "Extra S4: estilo de color con un LLM en GitHub Actions"
$git push -u origin lab/extra-estilo-llm

Qué debes ver

  • git status muestra solo .github/workflows/extra-estilo-llm.yml como archivo nuevo.
  • Tras el push, el run aparece en la pestaña Actions (si activaste Actions en el fork después del push, haz otro push).

Si falla

  • git pide nombre y correo: configúralos una vez y repite el commit.
Solo la primera vez
$git config user.name "Tu nombre"
$git config user.email "tu-correo"
Un run por cada push a lab/**. También se puede lanzar a mano con Run workflow, pero el botón solo aparece si el archivo está en la rama principal del fork.

D · Actions · antes de clase

Antes de clase y si no aparece en Actions

No aparece ningún run: comprueba por orden

  • ¿Está el archivo en .github/workflows/extra-estilo-llm.yml (ruta exacta, con el punto inicial y en la raíz)?
  • ¿El nombre de la rama empieza por lab/, como pide el disparador lab/**?
  • ¿Actions está activado en el fork?
  • ¿El YAML es válido? GitHub muestra el error de sintaxis. Si se pegó mal, copia de nuevo con Raw, sin retocar.

Dos casos más

  • Activaste Actions después del push: haz un push nuevo.
  • «Run workflow» no aparece: el archivo no está en la rama principal; usa el disparador por rama lab/**.

La víspera (profesor)

  • El workflow está en su ruta exacta y hay un run de prueba en verde con su enlace guardado como respaldo.
  • La pestaña Actions muestra el workflow y el run verde de respaldo está abierto en otra pestaña.

Si falla un job

  • Lee el primer paso en rojo: ahí está el error.
  • Los jobs siguientes salen skipped: no tienen nada que leer.
  • Descarga el artefacto nb-… de ese job para ver en qué celda se rompió.
  • En local: «No module named torch» = falta python -m pip install -r requisitos-extra-estilo.txt con el Python del kernel; ConnectError = proxy, usa el Codespace; el 03 y el 05 se leen sin ejecutar.
  • Avisos que no son fallo: «Node.js 20 is deprecated» y los de Hugging Face sobre peticiones sin autenticar.
