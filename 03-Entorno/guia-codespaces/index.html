Qué es un Codespace y por qué lo usamos

Qué es

  • Un ordenador Linux que GitHub te presta en la nube, con VS Code en el navegador o conectado a tu VS Code.
  • Se crea a partir de un repositorio y de un archivo de configuración: .devcontainer/devcontainer.json.
  • Trae Docker ya funcionando (un motor propio dentro del Codespace): no instalas Docker Desktop.
  • Todos usamos el mismo Python 3.11 y los mismos comandos, también quien no puede instalar programas.

Para qué lo usamos

Para lo que necesita Docker: construir la imagen de la API y ejecutar el contenedor (S2, bloque 4, 25 min). Trae también kind y kubectl para un laboratorio de Kubernetes en S3 (el laboratorio está pendiente).

Lo que conviene tener claro

  • No sustituye a tu entorno local: S1 y los bloques 1 a 3 de S2 siguen en tu equipo con env-ia-mlops.
  • Es temporal: si lo borras, lo que no hayas subido a un repositorio desaparece.
  • Tiene cuota mensual gratuita; hay que pararlo y borrarlo (diapositivas del final del curso de uso).

Cómo se cuenta

  • Hora de núcleo = horas de uso × núcleos. La máquina más pequeña (2 núcleos, 8 GB de RAM, 32 GB de disco) gasta 2 por hora: 120 equivalen a 60 horas reales (180, a 90).

  • GitHub avisa por correo al llegar al 75, 90 y 100 %.

Crear el Codespace del curso

En: tu navegador, con tu sesión de GitHub

Se crea desde la página del repositorio, eligiendo la rama develop.

  1. Abre github.com/helicr/curso-ml-ia-desarrollo-produccion e inicia sesión con tu cuenta personal.
  2. En el desplegable de ramas elige develop.
  3. Pulsa el botón verde Code y la pestaña Codespaces: verás Create codespace on develop.
  4. Mejor por ⋯ → New with options…: comprueba la rama (develop), la configuración (solo hay una: Curso ML e IA: de desarrollo a producción), la región (elige la más cercana: desde Perú, US East) y la máquina (2-core). Pulsa Create codespace.
Barra de direcciones del navegador
https://github.com/codespaces/newAtajo: elige repositorio y rama en esta página (también vale escribir codespace.new).

Debe salir

Se abre una pestaña nueva con VS Code en el navegador. La primera vez tarda unos 3 minutos en construir el contenedor y conectar (abajo a la izquierda pone «Abriendo remoto…»), y después unos 2 minutos más en instalar kind y el entorno env-ia-mlops. Al pie del menú de Codespaces, GitHub dice qué cuenta paga: debe ser la tuya.

Si falla

  • No puedes crear uno o se bloquea: revisa tu uso y cuota (diapositiva «Cuánto es gratis») y que entras con tu cuenta personal.
  • «Maximum running codespaces reached»: ya tienes otro encendido. Páralo en github.com/codespaces (⋯ → Stop codespace) y repite.
  • Pide permiso para hacer un fork: el repositorio del curso es público; acepta. Solo tienes lectura, y el fork se crea cuando haces tu primer commit.
  • Aparece «modo recuperación»: ve a «Si algo falla».

Orientarte y comprobar Docker

En: la terminal del Codespace

Cuando termine de prepararse, abre una terminal y comprueba lo mínimo antes de seguir.

  1. Abre la terminal: menú ☰ → Terminal → Nuevo terminal (New Terminal si está en inglés). Los comandos se ejecutan en el Codespace, no en tu equipo.
  2. El indicador debe empezar por (env-ia-mlops), como en tu equipo.
  3. Junto a la terminal verás la pestaña Puertos (PORTS): la usaremos después.
Terminal del Codespace
cd 04-Proyecto-Base
python --version
docker version

Debe salir

Python 3.11.18. docker version debe mostrar dos bloques: Client y Server (en el Codespace de prueba, Docker Engine Community 29.9.3). Sin Server, Docker no ha arrancado.

Si falla

  • El indicador dice (base) en vez de (env-ia-mlops): conda activate env-ia-mlops.
  • docker: command not found: la configuración no se aplicó. Paleta de comandos (F1) → Codespaces: Rebuild Container.
  • Solo aparece Client o dice Cannot connect to the Docker daemon: repite al cabo de un minuto; si sigue, reconstruye el contenedor.
  • Sigue sin ir: usa el bloque 5 (Actions), que construye la imagen por ti, y anota el mensaje exacto.

En el navegador o en tu VS Code: el mismo Codespace

VS Code en el navegador

  • Es lo que se abre por defecto al crear un Codespace en GitHub.
  • No instalas nada: sirve en un equipo donde no puedes instalar programas.
  • Las extensiones de la configuración del curso ya vienen.

VS Code de escritorio

  • Tu VS Code, con tus ajustes y atajos, conectado al Codespace.
  • Requiere VS Code 1.51 o posterior y la extensión GitHub Codespaces.
  • El código sigue ejecutándose en el Codespace (Docker incluido), no en tu equipo.
  • Puedes abrir el mismo Codespace desde cualquiera de los dos, y desde la línea de comandos con GitHub CLI.

Cuál elegir

Para S2 sirve cualquiera: los comandos y la cuota son los mismos. Si ya trabajas con VS Code (S0 lo instaló con sus extensiones), conectarlo te ahorra aprender otra interfaz. Si tu equipo no te deja instalar extensiones, usa el navegador.

Conectar desde tu VS Code de escritorio

En: VS Code (instalado en tu equipo)

Una sola vez: instalar la extensión e iniciar sesión. Después, cada Codespace aparece en una lista.

  1. Extensiones (Ctrl+Shift+X) → busca e instala GitHub Codespaces (GitHub.codespaces).
  2. Pulsa el icono Remote Explorer de la barra de actividades e inicia sesión con GitHub: pulsa Authorize cuando se pida (y, si el navegador lo muestra, Authorize Visual-Studio-Code).
  3. En la lista aparecen tus Codespaces: sitúate sobre el del curso y pulsa el icono del enchufe (Connect to Codespace).
  4. Alternativa, desde github.com/codespaces: menú ⋯ del Codespace → abrir en Visual Studio Code.
Terminal de tu equipo (opcional)
gh codespace codeOpcional: si ya tienes GitHub CLI (gh) con sesión iniciada, abre el Codespace que elijas en tu VS Code.

VS Code se reabre conectado: el Explorador muestra las carpetas del repositorio y la terminal integrada es la del Codespace (la ruta empieza por /workspaces/). Todo lo demás de la guía es igual.

Si falla

  • No aparece ningún Codespace: inicia sesión con la misma cuenta con la que lo creaste.

  • Equipo corporativo sin permiso para extensiones: usa el navegador, que no necesita nada.

Ver la API en el navegador (puertos)

En: el Codespace, panel PORTS

Con curl no necesitas esto: 127.0.0.1:8080 ya es el Codespace. Los puertos sirven para abrir /docs en tu navegador.

  3. Abre la dirección reenviada (https://<tu-codespace>-8080.app.github.dev; icono del globo o clic derecho → abrir en el navegador) y añade /docs.

La página de documentación de la API, servida desde el contenedor. La visibilidad del puerto debe ser privada (columna «Visibilidad»: Private): solo tu cuenta de GitHub puede abrirla. Cada visita aparece después en docker logs api.

Si falla

  • No pongas el puerto en «Public»: cualquiera con la dirección llegaría a la API, que no tiene autenticación.

En: la terminal del Codespace

Los registros salen por la salida estándar del contenedor; el usuario demuestra que no corre como root.

Debe salir

  • Si quieres repetir desde cero: docker rm -f api y vuelve a «Arrancar el contenedor».
  • Para la tarea, pega estas salidas en la plantilla de evidencias de S2.

En S2, bloque 4

No hay nada que guardar: son comandos que se ejecutan y se miran. Lo que sí te llevas son las salidas: cópialas a la plantilla de evidencias (01-Sesiones/S2-API-y-Docker/evidencias/).

Si cambias archivos

  • El repositorio del curso es de solo lectura para ti. Al hacer tu primer commit o push, GitHub crea un fork en tu cuenta y enlaza el Codespace a él.

Si no puedes abrirlo

  • Por ejemplo, porque se agotó la cuota: en github.com/codespaces, menú ⋯ del Codespace → Export changes to a branch. Sube tus cambios a una rama (o a un fork) sin abrirlo.

Hábitos

  • Activa Auto Save en VS Code.
  • Haz commit y push de lo que importe antes de borrar el Codespace.
  • Nunca guardes contraseñas ni tokens en el Codespace.

  • Lo puedes cambiar entre 5 minutos y 4 horas en Settings → Codespaces → Default idle timeout de tu cuenta de GitHub.
  • Un tiempo corto ahorra cuota.

3 · Bórralo

  • Parado y sin usar, se borra solo a los 30 días (puedes fijar de 0 a 30).
  • Con 0 se borra en cuanto se para: pierdes lo no guardado.
  • Cuando termines una práctica: ⋯ → Delete en github.com/codespaces.

Recuerda: el disco cuenta mientras el Codespace exista, aunque esté parado, y borrarlo no devuelve el disco que ya contó este mes. Si se te olvida, el borrado automático lo recoge.
